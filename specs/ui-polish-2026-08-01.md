# Storefront UI Polish — Addressing the 2026-08-01 Audit

## Goal

Resolve the eleven concrete gaps surfaced in the storefront UI audit (`2026-08-01`, branch
`main`). Eleven surgical changes, one PR, no behaviour or copy change beyond what each item
explicitly states. None of these touch the money path, the catalogue API, identity, or migration
code.

## Hard scope

Presentation + UX files only. The single exception is `pages/orders/[token].tsx`, which currently
renders with raw `gray-*` Tailwind utilities and is therefore the most visible off-brand surface on
the storefront.

### A. Accessibility primitives

1. **`src/styles/globals.css`** — add a `@media (prefers-reduced-motion: reduce)` block that:
   - Disables the global `transition` blanket on `a, button, input, select, textarea, .card-transition`.
   - Disables the `animate-fade-in`, `animate-fade-in-up`, `animate-rise`, and `animate-pulse` keyframes.
   - Sets `scroll-behavior: auto`.

2. **`src/components/ui/Modal.tsx`** — close button gains `sr-only` "Close" text so a failed icon
   load does not blank the only escape from the dialog. (Already has `aria-label="Close"`, keep both.)

3. **`src/components/ui/Toast.tsx`** — `aria-live` region gains:
   - `onMouseEnter` / `onFocusCapture` pause the auto-dismiss timer.
   - `onMouseLeave` / `onBlurCapture` resume it.
   - Each toast card is keyboard-reachable: `tabIndex={0}` so a sighted keyboard user can pause and
     dismiss it. Dismiss button stays as is.

### B. Z-index layering

Single, deliberate stack. Apply everywhere an overlay currently hard-codes its own z-index.

| Layer | z-index | Used by |
|-------|---------|---------|
| marketing header | `z-30` | `MarketingLayout.tsx` (`<header>`) |
| command palette / modal / drawer | `z-50` | `CommandPalette.tsx`, `Modal.tsx` |
| toast region | `z-60` | `Toast.tsx` |
| embedded checkout overlay | `z-70` | `EmbeddedCheckoutPanel.tsx` |

Files touched: the four above. The skeleton "Clearance overlay" at `globals.css:272` (`z-[100]`) is
left as-is — it intentionally sits above everything.

### C. Viewport units

Replace `min-h-screen` with `min-h-dvh` for primary surfaces so mobile Safari (URL bar collapse)
does not leave the page ~80px short.

Files touched: `components/ErrorBoundary.tsx`, `pages/orders/[token].tsx`.

### D. Focus styles

`PackCard` (in `pages/index.tsx`) gains a `:focus-visible` ring that matches its hover treatment.
Read the existing `border-text/15` hover pattern; the focus ring should be `focus-visible:ring-2
focus-visible:ring-focus focus-visible:ring-offset-2`.

### E. Loading skeletons

Wire `Skeleton` to the three surfaces that currently show bare "Loading…" text:

1. `pages/orders/[token].tsx` — order lookup.
2. `components/account/AccountPanel.tsx` — orders tab.
3. `pages/orders/success.tsx` — the polling "Resolving" state.

Use the existing `<Skeleton className="..." />` primitive. Sizes: a full-width bar at the title
position and 2-3 short bars for body copy. Do NOT redesign these screens — only replace the
un-styled loading copy with Skeleton blocks.

### F. Post-purchase page rebrand

`pages/orders/[token].tsx` is currently styled with raw `gray-50/100/200/500/600/900`. Rebuild the
markup to use design tokens (`bg-bg`, `text-text`, `text-muted`, `border-border`) and wrap it in
`MarketingLayout` so the buyer lands on a page that matches the rest of the site. Preserve every
behavioural guarantee in the existing comments (the download path resolution, the "permanent
access link" copy, the `download` attribute on the anchor).

### G. Pack detail — fetch error + breadcrumbs

1. **`pages/pack/[id].tsx`** — the `console.error('Error fetching pack details', error)` at
   line ~686 silently renders an empty shell. Add a calm, branded error state (use `ErrorState`
   from `components/ui`) that tells the buyer what went wrong and offers a "Try again" button
   that re-runs `fetchPack(id)`. Keep the SSR data path unchanged.

2. **Breadcrumbs** — a small `Breadcrumbs` presentational component lives at
   `src/components/ui/Breadcrumbs.tsx`. It receives `{ items: { href: string; label: string }[] }`
   and renders a `<nav aria-label="Breadcrumb"><ol>` with the last item as `<span aria-current="page">`
   (no link on the current page, per ARIA). Pack detail renders
   `[{ href: '/', label: 'Catalog' }, { href: '/ideas', label: 'Browse by category' }, { label: pack.title }]`.
   No data fetch — the pack is already on the page.

### H. Basket feedback

`components/cart/CartButton.tsx`:

1. The count badge (`<span className="inline-flex h-5 min-w-5 …">`) gains a one-time
   `animate-rise` plus a `data-just-added` attribute when the count increases. The `data-just-added`
   attribute is removed after 600ms (a `setTimeout` in a `useEffect` watching the previous count).
2. When `cart.remove(id)` runs from inside the drawer, fire a `useToast()` info message:
   `toast('Removed "X" from basket', 'info')`. The Add path already toasts on overflow only; this
   closes the asymmetry.
3. `AddToCartButton.tsx` reserves an `aria-busy="true"` slot while `!cart.ready` (currently a silent
   zero-height span).

### I. Polling progress affordance

`pages/orders/success.tsx` currently polls for up to 24s with a static copy block. Add a thin
progress bar (`<div className="h-1 w-full bg-border overflow-hidden rounded-full"><div className="h-full bg-primary transition-all" style={{ width: `${(attempt / MAX_POLL_ATTEMPTS) * 100}%` }} /></div>`)
above the existing copy. Width grows linearly with `attempt`. Once the phase resolves to `ready`,
the bar disappears; on `timed-out`, it fills red. No copy changes.

## Acceptance

A new static test file at `src/__tests__/uiPolishContract.test.ts` asserts each item by reading the
source as text (no DOM rendering — the existing convention from `storefrontDesignContract.test.ts`
and `packContents.test.ts`):

- A `@media (prefers-reduced-motion: reduce)` block exists in `globals.css`.
- Each of the four overlay files declares its target `z-{30,50,60,70}` class. Modal z-index test
  must NOT regress on the `shrink-0` already present.
- `Modal.tsx` close button contains `sr-only` text "Close".
- `Toast.tsx` declares `onMouseEnter`/`onMouseLeave`/`onFocusCapture`/`onBlurCapture` handlers.
- The four files that previously used `min-h-screen` for primary surfaces use `min-h-dvh`.
- `pages/index.tsx` PackCard class string contains a `focus-visible:` rule.
- `Skeleton` is imported in `pages/orders/[token].tsx`, `components/account/AccountPanel.tsx`,
  and `pages/orders/success.tsx`.
- `pages/orders/[token].tsx` source contains no `text-gray-`, `bg-gray-`, or `border-gray-` utility
  classes.
- `pages/orders/success.tsx` source contains a progress-bar-shaped element with `style={{ width:`.
- `pages/pack/[id].tsx` source contains the word `ErrorState` and a retry button labelled "Try again".
- `src/components/ui/Breadcrumbs.tsx` exists and exports a component that renders `<nav aria-label="Breadcrumb">`.
- `CartButton.tsx` source contains `animate-rise` and a `data-just-added` attribute, and a
  `toast(` call for the remove path.
