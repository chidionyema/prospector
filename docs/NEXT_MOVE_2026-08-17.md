## Why the fix is small: the repair tool exists and is pointed the wrong way

`tools/sweep_shelf_copy.py` already rewrites a breaching line, **re-grades the rewrite before
accepting it**, keeps every figure and institution, and can `--push` to the live catalogue. Its
docstring records it repairing 16 live lines on 2026-08-16.

It cannot touch a stranded pack, by construction — `live_rows()`, `tools/sweep_shelf_copy.py:233-244`:

```python
def live_rows():
    con = sqlite3.connect(f"file:{DB}?mode=ro", uri=True)
    live = listed_ids()
    for cid, title, one, created in con.execute(
            "SELECT candidate_id, title, one_liner, created_at FROM dossiers "
            "WHERE decision = 'pass'"):
        if cid in live:            # <-- stranded packs are NOT in `live`, by definition
            rows.append(...)
```

`listed_ids()` is the live catalogue. A pack is stranded precisely because it is not in it. So the
one tool in the repo that can fix `shelf_copy` is filtered to the exact population that does not
have the problem, and the population that does have it is unreachable.

## The work order

1. **`live_rows()` gains a population switch** — `--population {live,stranded,all}`, default `live`
   so today's behaviour is unchanged. `stranded` inverts the `cid in live` test. Nothing else in the
   sweep needs to change: `breaches()`, `rewrite_one()` and the re-grade-before-accept rule are
   population-agnostic.
2. **Report before fix**, per the existing tool's own contract: `--population stranded` with no
   `--fix` prints what would be rewritten.
3. **`--fix`, then re-publish** the rows that now grade clean, through the normal publish path
   (`tools/publish_passes.py`) so the publish gate — not the sweep — is what decides they may ship.
4. **Acceptance is the coverage tool, not the sweep's own report.**
